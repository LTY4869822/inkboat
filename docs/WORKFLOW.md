# 从选题到交稿

## 先说需求，少填表

正式写作会补齐选题、篇幅、字体与文风；你已经说过或明确沿用的信息不重复询问。没有题目时先推荐五个近七天候选，给出材料和角度，等你选择或明确委托。

篇幅支持轻量 1800—2500、标准 3000—4500、深度 5000—7000、自定义与自由发挥。统计正文汉字，不能把代码、图片中文字和来源附录凑进字数。题目需要哪些内容，比凑满数字更重要。

## 研究与文章类型

| 题材 | 应优先回答 | 常见问题 |
| --- | --- | --- |
| 消息报道 | 发生什么、如何发展、谁怎么说、影响是什么 | 只讲技术突破，不讲事情经过 |
| 同题测评 | 相同任务的输入、结果、失败与条件 | 不同任务的跑分混排，或假称自己实测 |
| 案例分析 | 目标、约束、动作、结果与可迁移部分 | 只有一句“效率提升”，没有过程 |
| 方法与教程 | 前置条件、步骤、成功状态、问题处理 | 跳过新手不知道的页面和验证 |
| 观点与人物 | 证据、处境、不同声音与判断 | 生硬套操作清单，或替人物编体验 |

Agent 应根据材料修正角度。证据反驳初始设想时，不能只删掉反例。未实际操作就说明案例来自公开材料，保留第三方自报、厂商展示与独立结果的区别。

## 写作与两道语言审稿

1. 先读资料、规划各节的作用，再按所选文风写草稿。
2. Humanizer 检查套话、虚假强调、重复结构等，保留风格和事实。
3. 独立 Lieflat 只在规则范围内清理，不把全文改成另一种写法。
4. 从普通读者的起点通读。结构返工后重新绑定两道审稿，不能拿旧记录覆盖新稿。

两道工具不负责证明“文章是人写的”，也不能保证读者一定喜欢。它们是编辑检查，不是作者身份鉴定。

正文默认不展示来源编号、文献附录或生图图注；内部 `sources.json`、`claims.json` 和图片来源照常保存。这不意味着可以把他人的发现写成自己的成果。平台申报字段与正文图注是不同的事。

## 配图与标题

读完全文再决定哪些位置需要真实截图、概念图或不配图。每张图应有删除后会损失的信息。标题截图、Logo 和日期不能代替结果、案例或操作画面。

标题在正文完成后提出不同角度的候选，并展示少量精选。每个承诺都要在正文兑现；不用“几分钟必会”“所有模型都输惨了”等无依据说法。

## 预览与工坊

Agent 生成十套真实排版，推荐一套，并打开本篇实际工坊地址。你可以：

- 切换排版、字体、字号、间距及组件。
- 调整标题与正文，保存当前文章，恢复历史保存版。
- 在预览关闭动效，保存静态版本。
- 另存排版模板，供后续文章调用。

**另存模板只存设计；保存文章才保存这篇的内容和设计。** 修改后点“保存当前文章”，再向 Agent 确认。无修改也可以直接确认当前版。

Agent 采用当前保存版，不能重新套默认排版覆盖你的修改。正文有变化时更新事实与图片映射，设计不必让你重调。

## 确认与交付

“给我预览”只授权本地预览；点保存也不等于授权发稿。确认后按本次要求交付本地文件或入草稿。正式发表需要明确指令，以及目标账号实际权限和平台验证。

`quality.json` 表示脚本检查和具体审阅项的状态，不等于新手试用成功、图片使用权自动成立或微信端已经通过。文章的价值和事实仍由实际阅读与核验负责。

可复制的指令：

```text
先给预览，不上传。推荐一套排版，并让我在工坊里改。
```

```text
确认使用已保存第2版，只存入草稿箱，由我自己审核发表。
```

```text
这篇正文改动了，请更新事实与图片映射后采用保存版，不要重置设计。
```
