# 搜索、截图与生图

## 不是“装上就打通所有平台”

墨舟会按文章的问题选择公开网页、官方公告、论文、GitHub 与相关平台。Agent-Reach、X Tweet Fetcher 等是读取或检索入口，平台是否可用仍由当前网络、登录、接口和宿主工具决定。

| 任务 | 首选 | 不可用时 |
| --- | --- | --- |
| 最新消息 | 官方公告与原始材料，AIhot 提供线索 | 真实公开检索，保留时间与失败记录 |
| 已知 X 链接 | X Tweet Fetcher 获取正文与媒体候选 | 宿主浏览器或公开索引，说明缺口 |
| X 关键词 | 实际可用的 Nitter 或授权站内检索 | 公开搜索，不伪称完整覆盖 |
| B站、抖音、小红书 | 实际原帖、视频与操作画面 | 可访问公开页或用户导入链接 |
| 原帖截图 | 宿主真实浏览器 | 原作者匹配画面，仍缺则逐项请求人工帮助 |

一个平台文本读取成功，不代表搜索和截图都成功。没有 X 账号不强迫登录所有平台；先利用公开材料，确需登录时解释缺哪项材料。不复制开发者 Cookie，不以绕过验证码或访问限制为工作流的一部分。

## AIhot 失败怎样处理

先区分本机连接拒绝、代理/权限、HTTP 状态和接口返回。保留一次真实诊断，不反复换 UA 或将缓存日期改成今天。AIhot 无效才切换搜索，不能悄悄把普通最近资讯标成“热榜第一”。

## 什么截图值得放进文章

- 报道：当事人的完整发言、时间脉络、争议双方及具体结果。
- 测评：相同输入、生成结果、失败案例、必要的模型与测试条件。
- 教程：普通人实际能找到的入口、关键操作、验证与成功状态。
- 图表：保留图例、样本、时间和适用范围，附近用中文讲清要看什么。

对普通读者优先选容易理解的结果与操作画面。复杂原始图表不是不能用，但不能让密集英文图例承担全文最关键的解释。

## 截图范围随场景决定

教程通常用完整一屏保留页面结构，再以红框定位；用户要求整页时按其要求采集，必要时补一屏帮助定位。整帖任务保留完整帖子与上下文。局部图表可以聚焦，但不删限定条件。

保留未标注原图，标注与来源都记录。不能用生图工具重画界面、修改按钮文字、替换数值、伪造验证成功或第三方中文翻译。无法自行获取时先找可靠原始画面，仍缺则明确缺哪一步、需要看见什么。

本仓库的**原版**截图标注工具支持其既有能力；不以独立教程版新增的箭头等扩展冒充原版已经包含。

## 生图不是固定配额

先通读文章，问“哪段信息用图会更清楚”。概念图可以说明关系、机制、对照或工作分工；装饰图不能充当证据，也不应重复正文。

有宿主内置生图能力时按内容实际使用；没有时询问是否配置、具体厂商与模型。用户不需要则不配置。某篇确实没有额外解释收益，可以记录具体例外。不能把一张封面算作正文生图来凑数。

封面和正文概念图分别定视觉方向。电影感封面不意味着每张操作图都要深蓝金色，也不意味着每篇都用同样两张图。

可访问不等于可随意再分发。图片原链接、采集时间、许可或使用依据与事实对应关系保留在内部文件。项目的 MIT 许可不改变第三方素材权利。
