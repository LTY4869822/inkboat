# 标题：具体承诺先于情绪

2026-10-04调研后补充本包规则。目标是提高点开的理由和正文兑现度，不承诺爆款。保留已装baokuan-title-generator的8维评分；以下规则优先于它的短标题习惯和未经核验的语料统计。

## 借鉴与证据边界

- [BigPengSays/bigpeng-hot-gzh的标题公式](https://github.com/BigPengSays/bigpeng-hot-gzh/blob/main/references/title-formulas.md)：把数字清单、具体产出、反常识、教程、可核验关注信号、同任务比较分开，而非六条同义改写。其语料库没有每篇独立原文和阅读数凭证，本包只借鉴结构，不宣称验证了阅读效果。
- [kangarooking/viral-title公众号规则](https://github.com/kangarooking/kangarooking-skills/blob/main/viral-title/references/platforms/wechat-public-account.md)：公众号标题需要对象、场景和结果；借鉴检索样例、去重与反馈回写。仓库自报的样本数量和阅读阈值未独立验证，不变成本包统计事实。
- [creator-buddy的标题skill](https://github.com/SpaceZephyr/creator-buddy/blob/main/gzh-Skills/baokuan-title-generator/SKILL.md)：保留多维兑现/具体/好奇/收益评价。其样本数量与本机描述不一致，不能照搬百分比作为研究结论。

没有复制外部skill代码、作者身份或整套标题语料。新样本必须存原始文章链接、作者、日期、实际可见指标、采集时间；指标不可见填null。只有标题结构样本时不得叫“已验证爆款”。浏览量与标题之间也不能直接推断因果。

## 生成与筛选

2026-10-04三个账号各50篇正文研究经用户确认后，将 [内容组织与案例论证](content-craft.md) 用于找标题承诺：从正文真实任务、关键差异、失败转折、成品、人的处境或步骤变化里提取点开理由。评测突出可比较差异，教程突出完成物与障碍，发布突出使用/付费决策，观点突出值得解释的矛盾。标题多项承诺逐项对应正文；疑问句也不能暗含已证实的错误前提。可学习“读者为什么关心”的构成，不复制作者标题句式、口头禅或未经复测的绝对化判断。本次是内容观察，没有点击率或爆款效果验证。

1. 搜索和写作前先写读者问题及暂定承诺，决定要找什么证据；标题在读完完整正文后定稿。不要最后只给发布名称加“来了”。
2. 内部生成12—18个候选，至少6个真正不同的角度；给用户展示3个最有区别的标题，推荐一项。用户直接要求固定标题时优先遵从，记录例外，不能偷偷改。
3. 默认偏好26—42个可见字符，不计空格，英文、数字、标点各计1；这是本账号的编辑偏好，**不是经过证明的点击率最优区间**。必要时可更长，短而有力也可保留，但须写length_reason。本包编辑上限64字符；实际公众号字段限制以当前界面为准，不为了凑长度加空话。
4. 前半句交代对象或受众，后半句提供冲突、具体变化、后果或可拿走的东西。检查信息流缩略显示时前半句是否仍有识别度。不能要求每个标题生硬塞满全部元素。
5. 每个候选内部记录reader、hook、promise、opening_reason、当前body_quote、method、8维scores、risk、risk_reason和evidence。body_quote必须真在本稿；多项承诺逐项人工对应段落。12个候选不能全是同一个“怎么用”换词。
6. shortlist记录3个ID，selected必须在其中。优先兑现充分、具体且有阅读动机的标题，不靠自己给所有候选满分证明好看。运行`research.py check --run RUN --scope titles`，再实际读缩略标题和全文。

用户明确给定固定标题时记录user_fixed={origin:"user",instruction:用户原话,title:指定标题}，允许只保存选定候选，不强制12项与3项短名单。仍核验正文兑现、字数、风险和实测真实性；不能把Agent自选标题标成用户指定。

## 六类可复用角度

| 角度 | 必须拥有的内容 | 原创结构示例，非真实爆款样本 |
| --- | --- | --- |
| 具体收益 | 可交付结果、步骤或检查单 | 一个具体工具，怎样把某项散乱工作整理成可验收的结果 |
| 条件反差 | 原始数据和限定测试条件 | 某项测试出现反直觉结果：选参数前该看哪些条件 |
| 同任务比较 | 相同输入、版本、成本和评价条件 | 两种办法做同一任务，差在哪一步，什么人适合哪一种 |
| 问题诊断 | 真实失败及原因，不凭空恐吓 | 某种结果一直不稳定，先检查这几个具体环节 |
| 案例拆解 | 谁做了什么、产出及局限 | 一个可追溯案例，拆出普通人能复用的步骤 |
| 变化与影响 | 新旧差异、开放范围、读者影响 | 一次具体更新，改变了哪些工作，哪些承诺仍待验证 |

数字只用正文已有且可核查的数；“我试了/亲测/花了几天”必须关联真实experiments记录。“最高/碾压/全面替代”需覆盖其声称范围的证据，单项评测不能扩大到所有任务。教程不要承诺固定时间精通，社交样本不能写成全民共识。情绪型候选最多一项，正文弱时不推荐。

后续用户提供实际发布数据时，记录标题版本、曝光、打开/阅读、日期、封面与发布时间等条件。只把有对照且可核验的观察写回“实践经验”；没有数据，不编造提升比例。


## 从材料选标题角度，而不是先填公式

2026-10-05按用户指令重读[bigpeng-hot-gzh](https://github.com/BigPengSays/bigpeng-hot-gzh/tree/8967879bbd59bfacfeb2d66214f095dc92b6f6bc)的skill、公式、选题模板、样本和检查单。此前已借鉴六类角度，本次补选择和兑现的细节，不复制七种公式目录、标题语料或作者身份。借鉴属于方法判断，不代表阅读效果已经验证。

先从当前正文或用户材料整理：明确对象、受众及任务、可数项目、已经展示的结果、真实取舍、投入/门槛、读者可取得的资源。用这些材料选择前文六类角度。无清单就不凑数字型；没有本人操作就用案例或第三方结果；没有相同任务的可比材料就不能用胜负型标题。用户只给短想法时可提待研究的方向，但不得把缺材料的候选推荐成定稿。不能仅标“需兑现”就把尚未发生的结果写成过去事实。

受众写进标题时，正文要有该读者特有的输入、交付要求或限制。例如写给小团队负责人，材料要解释多人交接和审核；写给初学者，要解释起点、账号和完成标准。不能把通用文章换一个职业前缀就称为场景化。已有正文不支持更窄的受众时，选符合正文的标题；只有用户同时要求改稿，才拓展文章。

附赠承诺单独验收：标题里的教程能跟到成功状态，提示词有完整可复制内容，脚本/仓库有已核验入口，模板能取得且说明填写方式。只有截图、提到资源名、计划以后制作或仅存在Agent本机的文件，都不等于读者拿到了资源。用既有titles的evidence/risk_reason记录对应位置与实际可用性；缺失时先移除承诺，只在本次已授权改稿范围内补材料。资源承诺检查不要求增加文献引用、来源附录或“AI生成”图注。

检查信息流截断时，前部仍应能辨认对象或问题。可用前16—20个可见字符作编辑预检，但它不是微信固定截断长度，也不强制工具名永远最前。受众、问题或关键差异哪个最能帮助理解，就先写哪个；保留本包26—42字符偏好和必要例外。

数字热度只能说明当时的关注信号，不能证明质量、稳定性或适合所有人。借鉴推荐/开源角度时，点开理由仍应落到完成哪件事、需要什么条件；不因Star高就写“必装”，不把开源直接写成免费运行。第一人称、固定时间精通、绝对替代与情绪用词仍服从事实与所选文风，不机械照收外部公式。

### 用户只要选题或标题时

只改标题：读取给定材料，按已兑现的价值给有差别的候选及推荐，不改正文或重做视觉。默认仍按本包12—18内部候选/3项展示；用户明确要N个就交N个，不为满足内部配额强跑正文流程。已有run沿用titles检查；没有run就在回复里说明承诺依据和缺口，不生成空文章、假质量报告或草稿授权。

只找选题：给读者场景、为什么值得写、核心问题和所需证据，暂定标题不冒充结论。无自选题按近7天五个最新热点规则；用户只想围绕一个关键词找角度时区分用法、对照、机制、问题诊断等适合材料的重心，不将同一热词换几个词当不同方向。不为差异而强塞不适合的类别。确认写文章后再进入正式问答和制作。
