# 把材料写成读者带得走的内容

本参考依据2026-10-04完成并经用户确认的150篇正文研究：夕小瑶科技说、数字生命卡兹克、卡尔的AI沃茨各50篇。此前9篇在本轮重新全文阅读，仅各计一次。原文及明确署名的完整转载均保留独立阅读笔记；样本并非连续最新50篇，内嵌图片视频没有全部观看。学习内容决策与论证，不学习排版或复制人设。代表依据见 [learning-evidence.json](learning-evidence.json)，完整研究记录留在用户工作目录，不随skill打包。观察到的写法没有点击率或读完率因果验证。

## 已确认的八项内容决策

1. **识别读者意图，并允许修正。** 搜索与大纲前提出读者、卡点、主要收益和阅读后可能改变的判断。已有信息直接推断；只有会改变工作方向的关键歧义才补问。阅读、采访或测试揭示更重要的问题时修正角度，不只搜索支持初始设想的案例。
2. **按主任务选材。** 在信息/干货下识别发布、评测、教程、案例、选型、研究、人物或观点。混合文确定主线，题材表是决策参考；不相关字段可删去，不强塞步骤、跑分和宏大结尾。
3. **搜索由问题驱动。** 列出支撑主要判断还缺什么，追到原始案例、结果、失败和限定条件，完整阅读再使用。平台数和搜索量不能证明深度；历史经验不能替代当前产品事实核验。
4. **让案例推进论证。** 技术任务保留问题、条件、输入、结果、失败/代价和归属；人物或组织保留角色、目标、约束、选择、不同声音及归属。写入正文时选择有用部分，使案例形成比较、递进、修正或流程交接。
5. **分别做好评测与教程。** 评测给可比输入、验收、结果、错误与成本，分开跑分、作品和外部/自身测试；教程给前提、可替换输入、预期结果、失败恢复和完成标准。其他题材不强制套技术字段。
6. **标题来自正文兑现的价值。** 提取真实差异、完成物、选择收益或值得解释的反差，逐项核对承诺，提供有区别的候选。标题长度服从信息，不用夸张因果、假亲历或未经测量的百分位吸引点击。
7. **写清判断的依据与边界。** 事实核验，解释给条件与替代原因，预测保留不确定，体验保留处境和归属。不能把他人结果变成我们实测；正文无文献编号与附录，不妨碍自然交代谁做了什么。
8. **按读者收益审稿。** 核对标题和开头兑现、普通读者能否看懂差别、是否获得本题需要的判断/方法/理解。保留有作用的场景、情绪和停顿，删无作用的重复和通用建议。篇幅不靠扩写凑数；图片回应附近内容并提供中文重点解释。

## 不同选题的内容重心

| 主任务 | 读者要得到什么 | 优先材料与组织 |
|---|---|---|
| 发布、新功能、大会 | 与我有什么关系，现在能否使用 | 改变的任务、新旧差异、入口/开放条件、费用与限制；区分演示与上线 |
| 对照评测 | 同样做我的事，差在哪，怎样选 | 可比输入与验收、并排结果、失败/返工、时间/成本、带条件的推荐 |
| 教程、技巧 | 完成第一件事，卡住怎样恢复 | 起点、依赖、关键操作、可替换输入、预期输出、恢复和完成标准 |
| 工作流、案例 | 原来怎样做，改在哪里，能否迁移 | 同一任务贯穿输入输出、交接、修改、人判断的位置和交付范围 |
| 合集、选型、付费 | 留用、换用或等待 | 按需求导航、现有工具是否够用、预算/平台门槛、替代方案及不必换的分支 |
| 论文、技术突破 | 到底解决了什么，结论成立到哪 | 原问题、机制、实验条件/基线、测量对象、结果/局限；发现、验证和证明分开 |
| 概念解释 | 理解概念并知道何时适用 | 定义、关系、通俗例子与场景，不为填表虚构实验 |
| 行业、职业、人物 | 现实为何如此，谁受益或承担代价 | 时间线、角色、资源/利益、约束、不同立场与反例 |
| 观点、现象、体验 | 得到更能解释事情的理解 | 具体观察、旧判断、可能机制、反例与适用范围；允许有依据的开放问题 |

趣味观察也可以以情节、意外和理解为主要收益。分类不决定固定段落数量，不要求每篇兼有新闻和操作干货。

本组样本可组合的长处：夕小瑶把新闻拆成机制与证据（X02的生成速度/总耗时、X28的发现/证明）；卡兹克用人的目标与反例修正判断（K07汉化组、K12驻场角色）；卡尔把能力落到作品和修改（C02短剧、C11选型分支）。这是内容观察，不是三位作者全部作品的统一定义，也不证明某种写法带来高阅读。

## 这次最需要纠正的写作决策

### 让读者先知道这篇解决什么

把宽题收成“具体对象在什么读者任务里带来哪种变化”。同一工具可因使用者的材料、交付要求、预算或权限不同形成不同角度，不能只替换标题里的身份词。选题的不同应体现为要回答的问题、所需材料和读完后的判断不同；既有reader-intent、topic.angle/reader_benefit和outline.materials足以记录，不再增加一套必填表格。

工具/合集推荐尤其要写“什么时候值得用”：每项连接到实际任务、起步入口与决定取舍的限制，允许结论是现有工具已经够用。原项目的热度、使用者身份和数字可帮助识别对象，但效果判断仍由本任务材料支持。新闻稿和概念稿也可提供理解收益，不为套工具教程而强加安装步骤。

开头尽快落到具体变化、任务、困境或值得解释的反常结果。不要用行业发展背景铺很久，再告诉读者本文用途。资讯可以先报变化；评测可以先展示关键差异或测试任务；教程可以先展示目标成品与当前卡点；观点文可以先给待解释的现象。不强制每篇以故事、问题或成品开头。

reader-intent的承诺要具体：读完能解释哪项变化、看懂哪种差异、完成哪个步骤，或更理解怎样的处境。不同收益用不同方式审阅，不要求个人感受量化成实验。标题与开头承诺共同约束材料选择，发现反例仍应调整承诺。

### 让任务推动功能出场

当主题是“怎样完成一件事”，用任务过程组织内容：在什么情况下遇到什么卡点，为何选择这项功能，动作是什么，产出如何，下一步凭什么继续。功能名称不自动成为章节名称。产品发布详解仍可逐功能介绍，但每项要解释它改变的工作环节、开放条件及尚未解决的问题。

有多个案例时选最能解释主线的案例展开，其余用于验证迁移、反例或边界。不要把每个案例都写成同长度的功能小卡片，也不把核心信息藏在截图里。篇幅增加应来自诊断、比较、迭代或机制，不能靠再说一遍“明确目标、核验输出”。

### 给读者可以检查的差异

“更有审美、更聪明、更稳定”不是完整结果。将抽象能力落到本任务的可观察位置：是否保留所需字段、物件是否穿插、相机是否对准主角、录制按钮是否能用、修改一个元素后其他元素是否保留。先说看见了什么，再解释为什么有意义。

描述图片或视频时，只判断真正看过的画面和操作。正文已读但视频未播放，作者的描述仍是author_report；不能转成我们的视觉复核或亲测。截图附近用中文指出看哪一处以及它影响什么；不因图片漂亮就保留，不参考样本的排版。

### 把“怎么用”写到读者能迈出下一步

方法文至少把核心任务的起点与验收说清：需要什么账号/工具/输入，在哪里开始，给什么要求，完成后应该看到什么，出现什么具体失败时如何换路。可以给可复制输入，但同时讲清哪些变量可替换、哪些约束决定结果，不能只贴长提示词就叫教程。

对新手给最短可行起步路径；可选的高级方式只在能解释取舍时加入。小白友好不等于隐藏权限、费用、版本和前置材料。已核验入口才能写确定按钮路径；时效性用法仍须回到当前官方说明，不能拿样本旧文当今日安装手册。

### 让建议由结果推出来

建议应能追溯到正文的具体结果：哪类任务使用哪条路径，牺牲什么、换来什么，何时值得升级或改方法。成本、速度、质量可能相互牵制；不能只拿每Token单价推整项工作便宜，也不能把不同客户端、预算或迭代次数说成同条件。

失败是解释判断的材料，不是附在末尾的免责句。讲清哪一步失败、证据是什么、原因是否已确认、尝试怎样改变；没复现的原因保留为假设。工具扫描成功不等于系统全部安全，网页3D效果好不等于可编辑建模资产合格。边界落到具体任务。

### 用案例带出思考

有价值的收尾解释本篇证据改变了什么认识，而不是统一落到“AI赋能、未来已来”。可以讨论成本结构、工作分工、创作方式或产品策略，但必须让读者看见推理桥梁。结尾允许短、允许保留问题；不为了制造震撼放大证据。

作者个人工作和反复遇到的问题可以形成叙事，但我们只能使用用户真实提供的经历、自己的实际操作或明确归属的第三方案例。不能把他人的通宵、费用、公司项目、攻击经历和观点写成我们的生活。

## 报道改稿的阅读终审

用 [news-reader-review.md](news-reader-review.md) 将人物反应、概念解释和事件经过接在一起，合并无增量纠偏，并检查截图是否打断阅读。语言审稿通过不能替代整篇阅读判断；需要改结构时回写作阶段，重新执行双重审稿。此规则来自用户确认的编辑复盘，不代表读者实测或流量验证。

## 落到现有流程，不另建一套表格

1. outline的每节purpose写清它推动了哪一步理解或行动，materials关联真正读过的材料；按价值分配篇幅，不平均凑字数。
2. 技术任务沿用cases/experiments；人物或组织案例用case_type=human_or_organization，保存目标、处境、选择和不同声音（见research-depth.md）。写稿时将最关键的细节放回正文，内部文件有记录而正文只给通用总结，仍算没兑现。
3. 通读时用depth-review现有reader_gain、body_quote、supporting_ids记录：具体细节如何支持判断，读者能复用什么，以及不同小节为何有信息增量。缺材料回研究阶段，不写一遍抽象建议补长度。
4. 标题的冲突来自真实取舍或发现：同任务成品差异、意料之外的失败、步骤变化或可交付成果。按titles.md核验兑现；不照抄样本标题或口头禅。

内容审稿时问三个问题：读者能否说出一处具体差异或新理解；需要行动的文章能否迈出有条件的下一步；关键结论是否来自展示过的证据。资讯和观点不强塞操作教程。单纯删除没有证据的感叹，不能替代补足实质材料。

## 原创迁移示例，不是已经执行的评测

若要评测AI整理报名表，不写“模型A适合复杂任务，模型B适合日常工作”。先设置同一份原始报名记录和目标文件，明确重名去重、手机号按文本保留、退订项剔除、冲突项另列这些验收点。实际生成后展示两份结果的对应位置，记录修复次数与任务耗时，再解释各自适合哪类工作。没有跑出来之前，不填胜负、准确率或效率数字。

同一思路也能迁移到资讯：解释一个新入口减少了原工作流的哪次切换，仍有哪些材料需要用户提供；再给当前已核验的起步方式。无需复刻作者的包子、天坛、宣传片、语气或叙事顺序。
