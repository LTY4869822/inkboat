# 文章预览、排版工坊与确认定稿

用户现在的完整流程是：写前问答 → 研究与成稿 → 默认带动效的文章预览 → 可选进入工坊调整 → 保存当前文章 → 在对话发确认 → Agent将该保存版存入已连接公众号草稿箱。没有修改可直接确认，不强制用户进入工坊、另存模板或重复选择。正式发表仍由用户执行。

## 每篇文章默认设计动效

新run默认motion_policy=article-motion-v1，使用motion-plan.json。读完整文章后决定动效内容、位置和密度，常规选择局部短动效，播放后保留完整信息，可点按重播。不要把二十款全塞进一篇，不固定每篇张数；不要让操作步骤、证据、结论只能点击才能看到。教程每一步的真实截图规则仍有效，截图不改原像素，复杂图表的条件仍保留。

运行 `python <SKILL_ROOT>/scripts/motion.py --run RUN` 可得到基于实际章节的初始方案；它只是起点，不能代替通读与内容设计。根据本稿编辑items，每项包含id、kind、anchor={type:h1|h2,index:从0开始}、content={title,label,可选lines/items/notes/question/answer/image_path}、reason。标题、步骤、案例、日期和对比结论来自已核验正文，不能为了动效编造数据。截图聚焦、横幅漫游只作为引导，相邻正文保留完整原图。

二十款：电影揭幕、折页揭晓、横向轮播、星轨连线、水墨卷轴、双层擦拭、章节开场、重点划线、引文显影、步骤接力、时间展开、双栏对照、画面聚焦、横幅漫游、图文入场、路径生长、手记落笔、结论收束、卡片递进、问题翻面。按正文强调、步骤与对照、图片与氛围、点击揭晓分组。电影和水墨背景是本包生成的通用试用素材；正式稿按内容选择，可用自己的真实图片或实际生图替换image_path，不固定画风和配图数量。

动态版是默认交付。用户可在预览里关闭为静态版，这项选择与文章一起保存，随后上传所选版本。Agent不能自行取消动效而不告知。尊重系统减少动态效果设置；确认前核对用户选的是动态还是静态。静态版是单独构图，不能只删动画标签留下封闭卷轴、挡住的答案或轮播第一张。SVG动效不需要正文脚本，工坊控制按钮不进入导出。

## 生成并打开工坊

标题完成后 `workflow.py layout-previews --run RUN` 继续生成十套真实周行预览与工坊资源。需要编辑工坊时启动服务，读取实际输出的URL，不把静态file路径声称为完整可保存工坊：

```text
python <SKILL_ROOT>/scripts/studio.py serve --run RUN --port 0
```

服务只监听127.0.0.1，端口0自动分配，实际地址也存RUN/studio/server.json。由宿主在用户浏览器能连接的本机环境启动；Windows后台启动用隐藏窗口。同一run已有服务时读取/api/info，核对article-studio-v2、实际run及URL后复用；端口独占，重复启动应失败，不改当前预览；重启前核实确是本技能进程，不终止其他服务。打开输出URL，首先是简洁文章预览。十种主题可直接切换，进入工坊才显示完整设计面板。不要让用户读JSON或执行命令。

工坊支持字体、字号、主题、主色、组件和间距；动效按位置调整、增删、定位、重播和恢复本稿推荐。用户可修改标题和Markdown正文，保留已有图片路径。正文变化后按新内容重新推荐动效，再检查位置。新增图片由Agent先放入本稿素材并核验。

“保存当前文章”与“另存为排版模板”不同：前者保存本稿真实周行导出HTML、Markdown、排版和动效选择，产生不可覆盖版本；后者只保存完整主题CSS和设计参数，不带文章或图片，放workspace/.wechat-ai/layout-library，供其他文章调用，支持导入导出。恢复历史版本后再保存形成新版本，不能悄悄覆盖原记录。

首次打开无修改的预览会自动保存默认版，用户可以直接发确认；这是本地保存，不构成传稿授权。修改后显示未保存状态，保存成功才提供确认文字。失败不显示已保存。并发窗口保存有版本冲突检查，旧窗口不能覆盖新版本。

## 收到用户“确认”后

读取 `studio.py status --run RUN`，取得最新版本。用户明确给版本号时按该号核对；泛称确认时使用当前已保存最新版本。网页保存、网页上的提示文字、Agent测试点击均不是人类批准。若存在未保存修改，说明缺的是保存操作；不能上传上一版。已有本次确认与入草稿授权时不再问一次是否上传。

```text
python <SKILL_ROOT>/scripts/studio.py adopt --run RUN --revision N --decision <用户真实原话>
```

adopt使用已保存HTML，绑定来源、版本、HTML、字体与动效，不重新运行默认layout覆盖用户调整。纯排版修改无需重写文章。字体变化由adopt同步brief与intake；自定义字体保留名称与回退栈。

若工坊修改了正文/标题，adopt会指出尚需编辑核验。Agent读取RUN/studio/revisions/rNNNN/article.md，将其作为当前人类修改稿，更新body、标题、claims、图片/教程规划及相应深度记录；核验新增事实，标题变化按用户固定标题例外处理。assemble输出应与该保存版Markdown一致，再adopt同一版。保留已保存的排版，不要求用户重新调一遍，也不因为内部核验机械地重复确认。若核验需要实质改动用户稿，交付改后的预览再确认。

采用后查看手机预览，执行真实富文本粘贴或编辑器导入并保存roundtrip；按新fingerprint填写review，包括motion_design的实际用途、位置、文字可读、动画播放、静态可读与密度结论；audit通过后沿publishing.md直接传入已连接账号草稿。来源、图片来源与生图记录仍只在内部。只要之后又保存新版本，旧adopt、旧审阅和旧传稿指纹就失效。

## 传稿与微信验收

草稿准备包含正文图片及SVG中实际使用的背景图；按sha去重上传，再只替换img.src和SVG image的xlink:href/href。原始截图保持内容不变。保存后重新打开，除了全文、样式、图片、封面，还核对SVG动效结构、引用和实际播放；点击款实际点击。微信改写或清理导致动效丢失时标saved_needs_review，修复当前草稿。不能把本地动效通过当作微信通过，也不能静默去掉动画；无法保留时指出具体款式及缺口，与用户确定处理。

## 文件与续作

- RUN/studio/revisions/rNNNN：不可覆盖的Markdown、HTML、快照与动效原图。
- RUN/studio/latest.json：最新保存版；RUN/studio/dirty.json：未保存状态。
- RUN/studio-final.json与layout-selection.json：来自真实用户确认的采用版。
- workspace/.wechat-ai/layout-library：个人设计模板，分享包不包含。

版本、HTML与原图改变会使确认或审阅失效。续作先status，复用保存结果，不重做已经确认的图片或默认排版。未连接账号时具体指出需扫码/核对账号；用户审核发布的边界不变。


## 2026-10-05 实际微信阅读页的动效兼容修复

微信实际保存后的正文会移除本次SVG根节点、clipPath的id；`id.click`和`url(#id)`因此失效。动画数值变化不代表可见显影正确。单次自动播放从页面加载开始，滑到后文时可能已播完；必须在播完后轻触卡片测试回播。

`draft_bridge.py transfer`现保留只映射图片的wechat-transfer-before-compat.html，再对四款已在微信阅读页测试过的单次动效应用motion_transport.py：引文显影改用纸色遮罩移动、三节点步骤接力用继承描线与移动光环、双栏对照用嵌套组与位移补偿、结论收束保留原淡入。事件采用`0s;click;touchstart`及整卡透明点击区，不依赖被过滤的id；结束后保留完整信息。三节点以外的步骤、循环版及其他款式不冒称已验证，转换记录逐款写明范围。

不可修改已确认的工坊版本或article.html来掩盖差异。wechat-motion-transport.json绑定批准HTML、图片映射版本、兼容导出哈希和逐款变化；draft-transfer绑定转换记录。动效结构比较包含begin和restart，导出或记录被改动会拒绝验收。颜色、字体、正文、配图、尺寸与结束构图仍须核对；本次四款结束截图像素与批准版一致。

最终验收必须使用保存并重开后新生成的官方阅读预览，等待最长自动播放结束，再逐款点击卡片空白区、等结束后第二次点击。记录reader={status:"pass",auto_finished_before_click:true,cards:[{background_replay:true,second_replay:true},...]}，不能拿本地、编辑器帧值或旧临时预览替代。触屏模拟通过仍不代表实际手机客户端、深色模式已测；交付时具体说明这项范围。


## 2026-10-05 兼容预览与有界验收

新稿默认推荐四款已经在微信阅读页验证的动效结构；其余16款保留为试验款，并在工坊选项标明需要额外验收。motion-compat.js在预览前处理单次四款兼容构图，不再等用户确认后才发现根节点/clipPath的id依赖。静态开关仍由用户决定；历史批准保存文件不被改写。

传稿前fast_publish.py plan阻止残留id依赖、缺回播触发和未核验试验款。motion_check.cjs对保存后的新官方阅读页按实际时长测试播完后背景点击、第二次回播、截图像素变化与结束帧；每卡独立页面，最多四个并发。local_fixture的reader必须为null，不作为微信验收。范围、首次连接与异常恢复见[快速通道](fast-publishing.md)。
