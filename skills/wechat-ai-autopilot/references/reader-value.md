# 题材决定读者所得

写之前确定读者的主要问题，写之后按实际稿件验收。文风和Humanizer只处理表达，不能替代事实、步骤和分析。

| 题材 | 应交付的内容 | 经常失败的写法 |
| --- | --- | --- |
| 教程 | 起点、准备材料、逐步操作与输入、成功信号、常见错误恢复 | 大段解释重要性，关键按钮却一笔带过 |
| 模型/产品对比 | 同题结果或明确不可比之处、可观察差别、费用/时间/设置、按任务选择与边界 | 只罗列发布参数，用不同作者不同提示的产出排总榜 |
| 新功能资讯 | 变化、谁能用、入口及实际用途、收益/限制、基于证据的判断 | 把公告改写成长文，没有解释与读者的关系 |
| 原理/分析 | 清晰问题、具体案例、机制、其他解释、读者判断如何改变 | 抽象道理加通用建议，不讨论反例与代价 |
| 人物/文学/叙事 | 具体场景、人物处境、不同声音和有依据的意义 | 为了“干货”硬塞步骤，或编造作者亲历 |

同一稿可包含多种段落，按主任务选验收类型，不固定所有文章结构。长篇的额外篇幅要用于展开案例、限制、解释或叙事；不能用同义重复补字数。

`reader_value.py init --run RUN --type tutorial|comparison|news|analysis|narrative`生成待审账本。通读当前正文后填reader、reader_outcome，每项写pass、当前body_quote和具体reason。不得只填“内容有价值”。例如教程的成功信号应是读者可观察的界面状态；对比的choice_and_limits应让读者按工作任务选择，而非笼统“都很好”。执行check，修改正文后更新哈希与受影响项。

首次onboard启用reader-value-v1，新run的audit将账本纳入检查和指纹；工坊修改正文后旧账本自动过期。旧已确认稿不追溯撤销，只在用户要求新改稿时迁移。结构检查通过不等于质量或事实自动通过。未做真实读者试用时reader_tested=false；真实反馈单独保存，不能把Agent通读叫用户测试。

模型评测只采用网上材料时，明确区分作者自报、真实公开产出、官方跑分和我们的分析。先确认模型、工具入口、版本与任务条件；缺少直接证据的项目不得计为该产品案例。跑分按同基准、同口径展示；不同设置注明不可直接比较。正文不列文献来源，但不得把第三方结果改称自己的实测。
