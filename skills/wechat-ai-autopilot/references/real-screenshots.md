# 真实局部截图与概念图混用

教程及文章中的教程段另读 [tutorial-screenshots.md](tutorial-screenshots.md)：从新手起点写到成功标志，每一步对应真实界面；自行截不了先检索可靠原始画面，仍缺就逐张报告需要的用户帮助。下面一般资讯稿“不要求每段一图”不豁免教程逐步截图。正文AI风格和数量另依adaptive-illustrations.md，不由封面色板约束。

资讯稿介绍发布公告，必须实际打开对应公司公告原始页面并截图；多项功能按需要截取各自说明或演示，不要求每段一图。干货优先实际操作的关键步骤与结果。正文数量由全文的信息需求决定，不固定截图或生图张数。至少1张有效真实截图是证据底线，不能理解成每篇只截1张。封面继续使用已认可的电影感杂志方向。

有效截图需要让读者看见正文所谈的功能、结论、数据及条件、案例产出或操作结果。仅有公司Logo、公告标题、模型名称和日期的截图不能充当有效证据图；需要交代发布日期时在正文说明即可。先问本图证明什么、为何这个位置需要原始画面，再定位区域。例如能力对比保留行名、列名、单位与测试条件；办公案例截产出与关键输入，不只截产品名字；教程保留操作位置及实际结果。只拍到标题就结束属于未完成采集。

## 普通读者的快速理解验收

选图同时考虑证据价值与理解成本。在来源可靠、能够支持同一事实的候选中，优先读者容易理解的原始案例产出、前后结果、关键操作与实际界面。复杂图表适合解释其独有的比较证据；不能因为它来自技术文档，就自动优先于更直观的原始画面。

对确需保留的复杂图表：

- 每张围绕一个读者问题。保留必要的比较对象、图例、坐标、单位、测试设置与影响结论的限定条件；拆图时两部分仍须有足够上下文，不能裁出一个高分数字丢掉条件。完整原图留内部复核。
- 在紧邻图片的正常正文里用中文交代“在比什么、最该看哪一处、能说明什么、哪些情况不能照搬”。按需要解释关键英文图例及横纵轴含义；不逐字翻译所有小字，也不只写“提升明显”。条件较长可放紧邻正文，但不得省掉或扩大原结论。
- 在390px实际排版宽度下，连同附近解释做一次扫读：普通读者无需熟悉评测缩写，也应能理解主要结果与边界。重要标记/数据难辨、英文图例过密或信息层次混乱时，优先换更直观的原始案例/结果图；必要时拆成独立局部，保留相同比较条件。不要把要求读者放大细读当作已通过。
- 保留原始像素，中文说明写进正文。不要重绘、翻译替换原图文字或用生图伪造更清楚的“官方结果”。概念图也需一眼看出关系或步骤，标签优先简洁中文。

逐图在visual-review.json对应项的checks.reader_comprehension写status与具体reason：读者能看懂的重点、图例/条件如何解释、手机宽度下仍存在的障碍。复杂图表另记录explanation_quote（本稿紧邻原句）与conditions_note（保留的关键条件）。检查的是图片加相邻正文的理解门槛；没有普通读者参与时这是编辑审阅，不声称完成了读者测试或测得固定理解秒数。

## 从文章需要选择截图，跨平台寻找原始画面

不把截图来源局限在官方文档。先写本段的可见证据问题，再找最直接的原始画面：能力比较找同任务成品和失败细节；教程找关键设置、输入与结果；成本判断找账单和任务范围；社会现象找原帖、不同观点及发生时间。截图来源随题材扩展，不要求每篇覆盖所有平台。

| 来源 | 优先截什么 | 必须保留的上下文 |
| --- | --- | --- |
| X / Twitter | 作者公开案例、结果、测试条件和明确结论 | 作者、原帖身份、绝对发布时间、相关输入/档位；相对“36分钟前”另存捕捉时间，不当原发日期 |
| B站 / 抖音 | 真正展示操作、失败或产出的关键帧 | 标题/作者关联、实际播放时间点、结果附近步骤；不用封面或评论代替视频效果 |
| 小红书 | 原创案例图、前后变化、关键过程与有效经验 | 原帖作者/时间、图片次序、适用条件；避免只截情绪化标题与成功宣言 |
| 产品、公告、代码仓库 | 功能入口、设置、可观察结果、差异/问题记录 | 版本与必要条件；开源README宣传图不能代替运行成绩 |
| 公开讨论与评论 | 具体失败、分歧、反例和原因 | 上下文及讨论对象，说明只是作者意见；单条评论不证明普遍现象 |

有授权浏览器登录时站内寻找并打开原帖，无接口时公开搜索索引、原文链接或用户导入均可；记录实际可访问范围，不能声称全平台已打通。平台要求登录/验证时依权限处理，不能用搜索结果截图冒充已读原帖。中文自动翻译画面另记translation=platform-auto，保留或核对原文，不把译文当原作者中文表述。

第三方操作或成品登记kind=public-case，关联已核验原始页面，并记录platform、author、post_time（时间精度/相对时间另记）、evidence_scope、必要时video_timestamp/input/settings/comparison_role。它不需要伪造我们自己的experiment。亲自运行取得的操作图仍用kind=operation并关联真实实验。

## 2026-10-04实际查看三位作者图片得到的经验

本次针对性视觉样本来自卡兹克的模型对照、卡尔的代码动画对照及夕小瑶的DeepSeek测试；仅覆盖实际查看的图片，不等于此前150篇文章的所有媒体已看。夕小瑶原微信页出现验证，实际查看的是署名与原链接明确的虎嗅转载；借鉴内容与证据选择，不借鉴排版。

- **成品与局部要成对。** 卡兹克把两种模型的摩托车成品上下放置并留模型标签，读者能直接观察细节；天坛的门与结构是可讨论的局部。我们应尽量对齐输入、视角、状态和尺度，再截正文要讨论的位置。不同镜头不能直接推成建模胜负；必要时先给整体，再截关键局部，不堆两张无差别首屏。
- **判断连着代价。** 其X案例截进了同提示、相同框架、作者、耗时、费用和具体评价；比只截“惊艳”有用。我们还需找到原帖及绝对时间，不能从文章里的二手截屏直接把作者自报升级为独立验证。
- **图里必须看见讨论的差别。** 卡尔对照的是相近场景中“只展示案例画面”与“画面加提示词”的成品帧，附近文字说明上下对应模型。静态帧支持构图与信息展示，不支持配乐、转场或交互评价；这些必须实际播放/操作。无需照抄原图的整块播放器外壳。
- **结果比回复更有价值。** 夕小瑶留下字数核对及继续修改的原始日志，还有标明日期、任务名和金额的账单局部，读者能看到返工发生和费用依据。裁切保留会改变结论的上下文，不能只留一个数字。主任务与账单的对应仍需要核验。
- **有用也可能难读。** 英文日志小字、双层净值/回撤图和数据表有证据价值，却不适合直接缩成手机长图。只取本段需要的日志/结果；复杂图表保留时间范围、比较对象与条件，再配中文解释。它们展示的是作者产出，不自动证明其中专业结论正确。

实际只裁原始像素，不抄作者对照拼图中的结论或重新合成假截图。相邻放置两张原图可由既有排版完成，内部记录先后和比较对象。若需要醒目标记，在正文告诉读者看哪里；避免改写证据图。完整原画面留内部，正文去掉导航、播放器无关工具栏、空白与推荐区，保留定位操作所需控件。

看图后的排除记录也有用：说明为什么标题图、首页、好看但不支撑论点的画面被弃用。读到DOM文本、拿到图片URL或下载完成不算实际看图，确认图片解码和像素内容后再写观察。

## 实际采集

核验原文时顺手采集，先读页面DOM和截图，定位与本段有关的标题/摘要、功能区、版本与入口或操作结果。不能用搜索摘要、聚合页截图代替公司原公告。用户界面的截图要保留实际步骤与实验记录，不能拿产品演示当自己的运行成绩。

使用宿主浏览器支持的局部截图API。当前Cua使用`tab.screenshot({clip:{x,y,width,height},fullPage:false})`，矩形来自最新DOM的`getBoundingClientRect()`与实际截图，读取`innerWidth/innerHeight`确认真实视口。内容不在视口内，先正常滚动、重新观察再截图；不调用evaluate改DOM来拼出画面。`clip`坐标单位按宿主文档，不能猜DPR转换。先读宿主screenshots文档确定输出编码；Cua目前返回JPEG，使用.jpg，不把JPEG存成.png。

2026-10-04复核同题游戏时，局部API两次返回Unable to capture screenshot，而普通getScreenshot成功。已实践的替代方法是保存完整原始视口JPEG，仅按实际像素矩形裁成PNG，不调整亮度、不改字、不重绘。完整视口只保留内部，正文仍插入有用局部。登记capture_method=browser-pixel-crop、original_capture_file、original_capture_sha256、pixel_operation=crop_only、output_pixel_size及实际viewport/clip；重新读取保存原图的真实尺寸，不沿用另一标签的尺寸。本次两张裁切与原图对应区域逐像素相等，真实记录通过、错误原图哈希被拒绝。该验证检查溯源，不能替代实际看图。

滚动后局部截图若落到页面顶部，先查看已保存的像素并读取`scrollY`，检查宿主此时用的是视口坐标还是文档坐标，不盲目重试。2026-10-04的IAB采集实际以文档y=2034取得DeepSeek两段说明，当时scrollY=1888，对应视口y=146。采集记录额外保存实际调用的`document_clip`和`scroll_y`，契约`clip`记录换算后的视口矩形，不能把换算值冒称实际调用参数。这是该次后端观察，其他宿主必须重新确认；不硬编码本次坐标。

一次截图只解释一个问题。保留完整标题/句子/关键功能及会改变理解的限定条件，去掉导航、侧栏、广告和空白；只裁切真实像素，不重绘、翻译替换、补字、移除限制或用生图美化。原站已有品牌和日期可保留，来源文件内部另记录完整页面。别截整页再缩成手机看不清的长图；区域太大时拆成独立截图。英文原图的要点在附近正文用自己的措辞说明。若截取附近内容会暴露个人信息，先选无敏感信息的区域或由用户提供可用截图。

检查截图像素、完整句子、遮挡与手机阅读宽度390px下的可读性；不能只看DOM文字正确。若页面加载失败或关键区域不可截，换同公司另一条已核验原始页面；仍无法取得时记screenshot_pending和具体原因，不把AI示意登记成真实截图。

## 登记与插入

官方公告链接的原始PDF可作为真实证据画面。先验证下载文件确为PDF，查看完整相关页，再只渲染完整图表区域；保存原PDF和SHA256、1起始页码、页尺寸、缩放倍数与裁切像素矩形，capture_method明确为pdf-render-crop，不冒充浏览器截图。保留图例、坐标、单位及影响比较的测试条件；条件过长可保留在紧邻正文的说明中，原始完整页留内部复核。手机下读不清时拆成独立问题或改用更合适原始图，不把整张长页缩小。PDF渲染仅需宿主现有PDF工具（例如PyMuPDF），核心工作流不强制安装它；不可用时换官方网页采集。

图像直接保存`run/assets/<语义文件名>.jpg`，采集记录保存在run内`<语义文件名>.capture.json`。sources.json记录该原始页面与发布日期/核验情况。capture至少含：

核验时正文尚未写好，可以先保存原图、采集时间、URL、矩形与用途；正文完成后补上真实insert_after原句，再正式register-image和check-images。不要为了提前登记而编造“本稿原句”，也不用为补插入点重新截图。

```json
{
  "kind": "announcement",
  "source_ids": ["S1"],
  "page_url": "实际打开的公开公告URL",
  "page_title": "实际标题",
  "captured_at": "实际含时区的采集时间",
  "capture_method": "browser-clip",
  "capture_sha256": "实际截图文件SHA256",
  "viewport": {"width": 1280, "height": 720},
  "clip": {"x": 338, "y": 432, "width": 600, "height": 215},
  "observed_text": "裁切区域中实际看见的文字",
  "insert_after": "本稿中对应事实段落的原句（至少8字）",
  "review_note": "具体文字、裁切范围、可读性和无改写检查"
}
```

数字仅展示已实测的矩形形状，下次以真实页面重新计算。操作截图kind=operation，source_ids关联实际experiment记录。页面URL不存会话token、密钥或登录信息；敏感URL先记录公开入口及实验定位，不能把原始敏感URL写进配置。schema校验不能代替真实采集与查看。

```text
python <SKILL_ROOT>/scripts/workflow.py register-image --run RUN --file <截图的绝对路径> --role body --backend screenshot --provenance notice.capture.json --prompt "真实公告局部：说明本次新增能力" --checked --note "已实际查看裁切，标题及功能完整，390px阅读可辨"
```

images-plan.assets对应项增加backend=screenshot与capture_record，写purpose、insert_after和source_ids。concept图用backend=native，各做各的用途。`body.md`在事实段落或操作步骤后插入`![具体内容说明](assets/notice.jpg)`，不另加来源引用、参考文献或「AI生成」图注。来源及裁切信息留sources/images/visual-review内部。截图不受AI图色板约束，可以在排版中留白，但不改变截图内容。

插图登记并写入body后先运行`workflow.py check-images --run RUN`，提前拦截缺图、全AI图、来源或裁切记录缺失和过期图片。通过后再按原流程assemble、周行预览、实际复制、accept-html及富文本往返。导出检查图片哈希、顺序和全文；新run的audit再次检查截图已插入而非只登记、原始页面匹配、采集哈希、局部矩形和有效插入锚点。变更图片会使旧排版确认失效，完成重建后按真实用户选择继续。

## 2026-10-05 完整一屏与操作框线

以下框线分支适用于教程完整一屏或用户明确选择；其他场景统一按[screenshot-strategy.md](screenshot-strategy.md)决定，不能将一屏规则套在中文整帖任务上。个人截图偏好保存在工作目录profile，不绑入发行默认。完整页面仍需有用的信息与紧邻说明。

完整未标注原图先存evidence。框线作为独立几何标注添加，不改变原图尺寸、不翻译替换文字、不重绘按钮和结果，不用生图模型重造产品界面。原作者或官方只提供表单局部时保留其原始范围，记录source_extent=provided-partial，不把它称为现场完整屏幕，也不补造背景；必要时寻找完整画面或具体报告缺项。

使用scripts/screenshot_annotations.py --original 原图 --output 标注图 --frames 框线JSON --record 输出记录。框选仅此分支按需使用Pillow，先检查宿主已提供；缺失时安装到工作目录隔离环境，核心编排仍用标准库。实际验证原始像素与标注图：输出必须等于原图加已声明框线，框内文字也不可改动。不是仅凭“看起来一样”认定真实。

自己采集用capture_method=browser-annotation，外部原图用source-image-annotation及kind=tutorial-step和真实tutorial_origin。保存original_image_file/sha256、完整viewport与clip、output_pixel_size、pixel_operation=frame_overlay_only、annotations数组、user_instruction原话及正常来源和插入记录。annotations每项x/y/width/height、color、stroke_width必须对应实际控件，不能画框造出新的结论。旧的局部裁切方式和已确认旧稿仍兼容。

完整一屏在390px检查框线能否定位操作，按钮名和输入要求由紧邻中文正文讲清；截图字太小时选合适实际视口、增加有必要的独立步骤，而非宣称放大后就已通过快速理解。保持原始界面，框线不等于已操作成功，也不以首页证明邮箱已验证。
