# 两类文章和原创口语写法

内容组织按 [150篇研究后确认的内容决策](content-craft.md) 执行。开头尽快让读者知道具体变化、任务或困境；核心篇幅按题材推进结果、差异、解释或人物处境。方法文由任务推动功能出场，给起点、可替换输入及验收；建议与收尾由材料推出来。复用现有outline/cases/depth-review，不新增机械配额或固定升华结尾。文风与排版仍遵从用户现有选择。文章学习单独走 [content-learning.md](content-learning.md)，不启动写作流程。

资讯 `news` 的承诺是把近期变化讲清楚。沿着具体发布/研究 → 核验细节 → 对特定人群的影响 → 编辑分析 → 下一步验证的路径推进。区分厂商自报、独立证据与编辑推论。没有直接比较实验不能给竞品胜负结论。至少一条核心事实原文发布日在本次运行时间的过去 7 天内；晚收录的旧文不能写「刚刚」。

干货 `practical` 的承诺是读者能照做。过程为任务与痛点 → 环境/版本/权限 → 真实输入 → 步骤 → 可观察输出 → 失败案例 → 适用范围。写 experiments.json，记录实际日期、命令或 UI 操作、版本、输入、输出文件、失败、局限。涉及接口成本但无法确认价格就不报价。未实操不冒充亲测，使用 brief.practical_mode=documented 并在开头说明。

采用 khazix-writer 的高层写法，不复制作者原句、个人身份、经历、固定尾部或联系方式。段落通常 20—90 汉字，短句与解释段交替，具体细节先出现，再解释机制。资讯可以连续叙事，不强制小标题；方法文可用少量语义标题提高手机扫读效率。观点保持有依据的原创判断，不靠堆口头禅、脏话、情绪标点或自嘲数量模拟作者。仅引用真实材料并短引；用户没有表达的商业立场不代替其宣布。

L1 扫描虚构实测、冒充签名、占位符、无证据事实。L2 检查开头、转场和阅读节奏。L3 检查来源是否直接支持段落、独立性、类型承诺与边界，区分事实、解释、预测与体验。L4 通读，删除没有推进作用的重复和说教，保留有作用的场景、情绪与停顿；不要求每段增加一个数据点。`review.json` 保存每项 status 和具体 reason；不填机械「都通过」。禁用词由质量报告给出警告，不让引用和源链接里的符号造成风格假失败。

正文默认不展示引用与来源附录，不加图片生成来源图注；核验映射在内部 claims 的 body_quote/locator 保留。原创判断应占有分量，发布事实仍自然标明是哪家公司做的。大会详解按功能/模型展开：用途、入口和开放条件、具体任务写法、我们的判断；标明仍在预览或未来推出，不给未核验的按钮路径或假使用成绩。

## 篇幅与素材诊断

输入诊断决定从哪里开始：只有念头先找值得展开的问题；多链接先提炼主线；草稿先定位缺少证据、结构或案例；重写先写病灶，不做泛泛润色。已提供的资料不再索要。用户选全自动时，直接组织素材和字数预算，不要求每节确认。

`outline.json` 示例结构：`{"reader_promise":"读完能判断哪些动作可交给AI", "input_mode":"sources", "sections":[{"question":"这次发布改变什么", "purpose":"交代已核验变化与读者处境", "materials":["S1"], "target_chars":450}]}`。所有预算总和落在 brief 的范围。标准文把机制、案例或操作作为重心；深度文增加真实对照、失败边界或不同任务场景，不再复述开头。

写完按 `prose_cjk` 统计。字数够了再审信息增量：每节回答不同的问题，具体例子承载推理；长文需要语义小标题，段落保持手机可读。缺少足够材料时继续检索或实测；仍不足就报告缺项及实际篇幅，不能将不足范围标成通过。用户若有个人文风档案可以读取，抽取节奏与表达偏好，避免抄取其他作者的身份、经历、政治商业立场和固定签名。

V2 的 review 另含 `length_depth`（篇幅与内容深度）、`layout_fit`（本稿和所选周行主题的匹配）、`visual_design`（图像设计效果），均需具体理由。程序只能检查记录和字数，实际阅读仍由 Agent 完成。

## 标题评分

最后调用 baokuan-title-generator，并执行 [新版标题规则](titles.md)；评分采用兑现度25、相关性15、具体性15、好奇15、收益10、情绪10、清晰5、独特5。内部12—18候选、至少6个不同角度，展示3个推荐。默认偏好26—42可见字符，理由充分可例外；每项保存当前正文兑现段、读者收益和点开动机，不只打分。不能保证十万阅读，未核验语料统计不作为证据。

缺少标题 skill 时使用上面的 8 维规则，与原版调用区分为 builtin-fallback。最终推荐兼顾兑现与点击；高风险或无正文支撑的候选不选。`selected` 用候选 id，`body_sha256` 用 fingerprint 输出中的 body_sha256。摘要 60—100 汉字，独立兑现读者收益。

新run另按 [全网研究和逐节深度](research-depth.md) 保存真实案例/对照、平台覆盖日志和当前段落。长文至少两处实质证据展开并含案例或比较；这只是底线，不限制素材与图数。通用建议无证据和迁移示例时不算实质单元。


写作之后、配图之前执行[Humanizer审稿](humanizer-review.md)，先保留当前选定文风草稿，再改写套话和重复。教程以可跟随的操作为主，保留真实误区与具体判断，不用内容承诺和升华反复占篇幅。清理不创造真人经历，不删除必要条件。
