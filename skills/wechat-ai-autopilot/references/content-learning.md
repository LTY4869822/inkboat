# 文章学习：读全文、提炼、确认、合并

适用于用户提供好文章链接、指定账号与篇数、比较多个账号、补充某类选题的写法，或要求续读之前的学习批次。学习只分析用户指定范围；默认看内容，不参考排版。仅学标题时明确为标题研究，不能把它计入全文阅读。学习不自动写新文章、使用公众号登录或触发草稿传送。

用户给的是另一套skill仓库并要求借鉴方法时，直接走末尾“学习另一套skill的方法”，不套文章篇数与learning.py全文契约。

## 输入与进度

已有链接就处理这些链接；已有账号和篇数就按该数量推进，不再次询问写作选题、篇幅、字体和文风。只在账号歧义、缺少阅读数量或日期范围会明显改变工作量时合并补问；可先完成不受影响的阅读。不把本次每人50篇变成所有学习任务的默认数量。

先读当前SKILL.md与content-craft.md，知道已有规则。创建工作目录中的独立 `wechat-content-study/<批次>/`，不用skill目录存全文、Cookie或个人操作记录。`learning.py init --workspace WORKSPACE --request-file REQUEST.json` 初始化，返回run；也可用 `--run RUN` 指定批次。已存在的study.json不能被init覆盖，续作先status。

REQUEST.json由Agent根据用户原话生成，不让用户手填：

```json
{
  "request": "读两个账号各20篇，研究评测文章怎样体现差异，先给总结",
  "targets": [{"account":"账号甲","count":20},{"account":"账号乙","count":20}],
  "focus": ["读者收益","标题兑现","案例比较","判断边界"],
  "layout_analysis": false,
  "approval_policy": "review_first"
}
```

单批链接可用一个用户认可的目标标签，真实账号仍逐篇记录。优先近期且覆盖不同题材；用户要求连续最新、具体月份或特定类型就照办。无法取得指定范围时准确报告缺口，未获授权不把早期文章静默充作“最新”。日期记录原文或转载的实际口径；作者个人署名与账号归属分开。

## 找文章与真正阅读

优先用户原链接、账号公开目录和正文内链，再用公开索引定位。原文不可读时可读取明确署名、连续至实际结尾的公开全文转载，记录实际读取页面和未核实的原始日期。登录、验证或付费限制遵守宿主访问规则；不能把验证页面或部分正文计为读完。

公开HTTP用于普通文档获取，浏览器用于可见页面与需要目视的材料；宿主接口与权限以当时可用能力为准。沿已定位的页面读取，不猜私有接口、伪造平台覆盖或盲目重试同一阻塞。一次路径失败不等于全文不存在；换可合法读取的路径时保留实际访问方式与范围。

下载成功、正文被保存、清单有标题，都不代表已读完。全部文字实际进入阅读上下文，输出截断时补读缺失部分，才记录read_complete。短文也能计入，须说明完整性依据；媒体有独特信息时实际查看或播放相关片段，逐篇区分文字、图片、视频、外链范围。作者展示的效果是作者报告，未看过的画面不当作我们的视觉验证，未复跑的测试不当作我们实测。

每篇记录唯一id、目标标签、真实账号/署名、标题、原文/读取链接、日期口径、正文文件SHA256、状态与完整性依据。研究记录保存在articles.json，每条内含notes。正文文件可以位于本批次或同一工作目录的已有研究批次；引用绝对路径仅留个人研究记录，不写进分享skill。

```json
{
  "id":"A01", "target":"账号甲", "account":"账号甲", "author":"实际署名",
  "title":"原文标题", "read_url":"https://example.com/article",
  "original_url":null, "published_at":null, "date_kind":"unknown",
  "status":"read_complete", "full_text_file":"text/A01.txt", "hash":"实际SHA256",
  "completion_basis":"实际读到结尾的依据及截断补读情况",
  "notes":{
    "topic_type":"同题评测", "reader_promise":"读者需要做出的选择",
    "hook":"从哪一具体问题进入", "argument_or_case_sequence":["正文怎样推进"],
    "concrete_detail":"会改变判断的具体材料", "short_anchor":"正文内短定位锚点",
    "transferable_lesson":"观察到的内容决策及迁移理由", "limit":"适用条件与保留意见",
    "media_review":"完整文字已读；图片/视频实际查看范围或未看范围"
  }
}
```

未读线索标lead_only，访问受阻标blocked，不填read_complete。`learning.py record --run RUN --file ARTICLES.json`接收单条或数组，按id更新进度；同id续读更新，不新建重复文章。`learning.py status --run RUN`显示有效完成数与剩余；`check`检查目标数量、重复标题/链接/正文、文件哈希、短锚点和笔记字段。检查仅证明记录一致，不证明理解、媒体覆盖或文章事实正确。

跨批次沿用已读材料时检查原文件、笔记与范围，准确标记“沿用”，不能宣称重新阅读；用户要求新增N篇就排除已读文章。用原文标识、链接、题名和正文哈希识别同一文章的多个转载。续作保留有效成果，修复失效记录后补足实际缺额。多账号可分批推进；并行agent须符合用户授权及宿主规定，不因篇数多自动委派。

## 提炼与交付

先逐篇回答：读者为什么点开；题材如何决定内容；哪些材料承担判断；段落怎样比较/递进/转折；哪些细节和边界不可省；哪些表达不该吸收。技术任务和人物体验用各自的观察尺度，不把所有文章写法压成一套“痛点—工具—效果”。

跨文章比较共同点、差异和反例。多人供稿账号按真实署名解释；少量某类样本不足时不概括整个账号。不用标题、公开热度或作者自述直接证明点击率提升。历史技术事实另需当前一手来源核验，学习笔记不充当产品说明书。

写summary.md（或report.html）及lessons.json。每条候选经验包含：

```json
{
  "id":"L01", "rule":"能改变下一次写作决策的规则",
  "why":"它怎样帮助读者，何处体现", "evidence_ids":["A01","A07"],
  "applicability":"适合哪些选题与条件", "limits":"不适用范围及反例",
  "proposed_location":"references/content-craft.md相应决策",
  "relationship":"refine", "confidence":"content_observation"
}
```

证据数量按判断需要，不设每条必须来自几个作者的配额。规则未能从实际材料支持时不纳入；可能没有新规则，可以解释现有规则已覆盖什么。提供原创迁移示例，但未执行的示例不填结果，不复制原文句式、标题、人设、联系方式或他人亲历。

交付实际完成数量、取文路径与日期范围、媒体阅读范围、逐篇清单、按题材总结，以及候选规则及拟修改位置。用户要求先确认时保持skill原样；部分完成就标剩余，不能称目标全部完成。已明确授权直接合并时，先形成可审阅总结，再在授权范围内执行，不重复问同一权限。

## 确认后的经验合并

把用户原话、批准的lesson id及范围写integration.json。对照现有规则：相同经验增加依据，不重复追加；更精确的经验补适用条件；冲突经验比较证据后提出替换，已有用户偏好优先。修改目标参考文件，在SKILL.md保留可发现的入口，不把每次研究报告粘成永久上下文。

合并题材重心、判断与检索方法，避免固定段落数、配图数、案例数和作者式结尾。内容学习不新增写作风格或改变字体、排版、账号和发布约定，除非用户另有要求。来源、阅读范围及改动前后哈希保留内部；全文和个人资料不进分享ZIP。

修改后运行skill-creator的quick_validate、相关脚本验证及引用检查；新增/修改脚本实际执行，验证的是记录与行为，不冒称阅读质量或阅读量效果已证明。新包仅打包skill资源。以后写稿按相关题材读取已合并规则，不重读全部历史语料。


## 内容学习与文风学习分开

本文件默认mode=content：总结可迁移内容经验，默认先交用户确认。明确“提炼文风并自动加入文风选项”时改走[文风蒸馏与风格库](style-distillation.md)，request.mode=writing-style，按用户授权使用explicit_delegation，完整学习、规则与样稿审阅通过后自动register，无需重复询问。只下载全文、已有内容学习报告或作者名字不能自动生成可用文风。用户提供的全文文件可记source_kind=user-file、input_label=实际材料名称、read_url=null，全文保存在研究目录；不能给本地文件编造公网链接。


## 学习另一套skill的方法

用户给GitHub或skill链接、要求吸收其中有用经验时，先读取入口及被引用的相关方法、示例和许可证，固定可读取的版本并留文件哈希。把它作为方法研究，不能把标题列表或作者自称的语料数量计入公众号全文阅读。项目宣称的爆款、提效或覆盖率没有独立数据时只是作者描述。

在独立研究目录保存sources.json、lessons.json和integration.json，对照现有规则逐项标注新增、细化、已有覆盖及不采用的原因。用户已明确要求写入时直接落实有用增量，不再要求确认；用户说先交总结则保持原skill。保留现有偏好，不能因参考项目就换排版、文风、截图、生图、动效或发布通道。

按触发任务把经验放回现有参考文件，SKILL入口简短可发现。不安装或执行整个仓库来代替阅读；确实需要其代码另按授权、能力和许可证处理。原样代码/大量文档须保留许可，不把原创改写的方法总结称为安装了上游完整skill。外部文风也不能仅凭作者名自动注册，仍走writing-dna蒸馏与样稿校验。
