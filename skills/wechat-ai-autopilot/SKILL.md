# 墨舟 InkBoat · 公众号创作工坊

在当前Agent会话中完成内容生产。脚本负责状态、契约和验证；搜索、写作、内置生图由宿主工具完成。传稿优先官方API或独立浏览器DOM脚本，桌面坐标操作只作能力缺失时后备。默认在用户选定排版且无待改内容后存入已连接公众号草稿箱，由用户审核发布。用户要求只做本地稿时遵从。流程需要宿主工具与有效登录，不是定时后台服务。

正文默认 presentation={citations:"internal",image_captions:"none"}：无来源编号、文献引用、来源附录或「AI生成」图注。sources.json、claims.json、images.json保留内部，事实核验不降低。使用原创措辞与分析，不把别人的发现冒充自己的成果，不虚构现场、界面或使用经历。平台有实际标识字段时依其要求办理，正文不自动加图注。

## 先选择任务模式

- **只选题或只改标题：** 用户只要方向或标题时读[titles.md](references/titles.md)，只交付该项；有具体题目/草稿就不再推荐热点，不启动正文、配图、工坊或传稿，也不问仅写正文才需要的篇幅/字体/文风。用户随后要求写文章，再补写前缺项。正文未完成时标题是待核验候选，不把设想写成已取得的结果。
- **写作或改稿：** 进入下面的问答与制作流程，写前读 [内容决策](references/content-craft.md)。按发布、评测、教程、案例、选型、研究、人物或观点决定重心；读者收益是可随证据修正的判断，不把每篇套成同一结构。
- **内容与方法学习：** 用户要求读好文章、研究某账号、总结经验、借鉴其他skill的方法或继续补读时，先读 [文章学习与经验合并](references/content-learning.md)。公众号全文使用 `scripts/learning.py` 保存文章进度；仓库方法使用该参考文件末尾的独立学习分支，不计入全文篇数。此模式直接处理用户给定材料，不启动写作问答、热点竞选、生图、排版或草稿传送。默认先交总结，用户确认后合并规则；已明确授权的经验直接落实，不重复索要确认。
- **文风蒸馏与新增：** 用户明确要求学习文章的写作风格并加入选项时，读 [文风学习与风格库](references/style-distillation.md) 及其链接的writing-dna原始流程。宿主真正阅读全文，提炼五份文档并写原创样稿验证；合格后按已授权的自动新增要求注册。仅学习内容经验不自动新增文风；用户要求先确认时才等待批准。
- **学习后写作：** 用户同时提出学习与写作时分别记录进度，按当前授权完成相应学习模式，再用已选文风写新稿；写作问答、排版及传稿约定照常执行。

## 启动与写前问答

将本目录记作SKILL_ROOT，不硬编码用户名。首次使用读[能力检查与配置](references/onboarding.md)，执行`onboard.py doctor --workspace WORKSPACE`，按实际工具快照和缺项给最短可行路径；执行`onboard.py setup --workspace WORKSPACE`启用新版验收并合并个人偏好，不授予上传权限。续作复用有效配置。宿主实际检查搜索、生图与浏览器，不把文件存在当调用成功。适用项目的路由约定照常执行。

正式写文章前读 [写前问答与选择记录](references/intake.md)，一次合并询问缺项。已给答案不重复问，明确委托的字段可代选并记录原话；沉默不代表委托。

1. 选题：用户有自己的题就按其意图写，不擅自换成热点。没有题则先搜近7天五个真实候选，附原始发布日期、实际关注信号、角度和读者收益，推荐一项，等待用户选择或明确委托。
2. 篇幅：轻量1800—2500、标准3000—4500、深度5000—7000、自定义，或根据内容自由发挥。统计正文汉字，不把代码与图片文字凑字数。自由篇幅在outline.json记录实际预算及length_reason。
3. 字体：正楷/楷体、宋体、微软雅黑、苹方、系统无衬线，支持填写自定义字体名称。字体在十套预览及导出保持一致；普通正文、列表正文与普通表格单元统一黑色，标题、强调词、链接、代码和标志性设计保留各自颜色；未安装字体的读者设备可能回退，不能承诺所有设备同字形。
4. 文风：通过`style_library.py list --workspace WORKSPACE`读取卡兹克与用户已经蒸馏完成的风格，动态提供选项，不把未学成的作者列进去。用户可提供大量文章学习新风格；已明确沿用某风格不用重问。新风格五份规则与样本在工作目录，损坏或缺失不能静默退回卡兹克。

第五项排版在成稿后展示带动效的真实预览，用户可直接确认推荐版，也可进入工坊调整后保存再确认。先前已指定排版也生成全部预览，标明其选择，不额外强制重问；新稿的首次选择仍须绑定当前成稿。明确「先让我选」优先于一般「全自动」。

`intake.py questions --workspace WORKSPACE`读取当前风格库并生成缺项提示，由宿主展示并收答复。创建独立run：`workflow.py init --workspace WORKSPACE --type news|practical --topic TOPIC`。新run为schema3，默认值不等于已回答；`intake.py apply --run RUN --answers <实际答复JSON>`记录四项后才正式写作。未知选题可先建立待回答run保存搜索结果。所有后续命令带--run。参考 [选项](references/preferences.md)、[写法](references/editorial.md)、[契约](references/contracts.md)。

发行默认面向普通AI使用者，封面采用克制杂志方向；个人已选电影感等偏好由工作目录profile承接，当前请求优先。通常1张封面；正文图数由全文的信息需求决定，不固定截图或生图张数。常规正文同时使用有价值的AI插图与真实截图，封面不抵扣正文。先检查宿主内置生图工具；有则实际使用，无则询问是否配置及具体厂商/模型，用户拒绝则省去AI插图。确实无增益的稿件记录具体例外，详见 [生图能力与配置分支](references/image-capability.md)；每张概念图最多修复1次。标准篇幅仅在用户明确委托决定时采用。继续已完成文章时不重新启动问答或改变其现有字体与主题。

## 制作顺序

**教程与正文配图：** 教程或文中的教程段读 [逐步教程与缺图处理](references/tutorial-screenshots.md)，从普通读者的起点写到可确认的成功状态，每个实际操作步骤配对应真实截图。先自行采集，无法取得再找可靠原始教程画面，仍缺则逐张告知用户需要的人工帮助，不跳步宣称教程完整。正文AI图读 [按内容决定插图](references/adaptive-illustrations.md)，逐段决定用途、插入点和适合的风格；不继承上一期张数，不强制套用封面的电影感、配色或3D风格。

新run启用tutorial_policy=step-screenshots-v1、illustration_policy=content-fit-v1、motion_policy=article-motion-v1及studio_policy=saved-final-v1。reader-intent.article_type=tutorial或tutorial_sections非空时必须有tutorial-plan.json；每步记录完整说明与真实图。images-plan记录每张正文生图的style_decision及全文density_review。check-images和audit检查缺图、待人工环节和规划记录；自动检查不代替实际看图与跟步骤核验，旧run不追溯撤销确认。

研究前先读 [内容决策](references/content-craft.md) 和 [读者意图与同题评测](references/reader-intent-and-evaluation.md)，写reader-intent并按题材决定读者收益。遇到反例或更重要的问题要调整角度，不能只搜支持初始设想的材料。评测必须以相同任务的真实输出与差异为主，不能改成泛泛的选型方法；新闻、教程和观点采用各自适合的价值形式。搜索后端按 [已验证的搜索扩展](references/search-backends.md) 检查，skill存在不等于平台已连接。 用户指定的 Agent-Reach 按 [新增搜索通道](references/search-agent-reach.md) 接入，使用独立环境与固定版本，实际查询后再判断连通；网页读取与关键词搜索、登录态和截图分别验收。 X原始素材按 [推文快速读取与真实截图](references/x-materials.md) 执行：已知链接先用内嵌x-tweet-fetcher获取文本与媒体候选，关键词搜索按Nitter实际配置或宿主检索，截图及独立长文仍交宿主浏览器。

1. **发现与选题。** 自选题跳过热点竞选，直接核验材料；无题先读aihot的SKILL.md，搜当前热点与滚动7天。discover使用匿名v1客户端，无需AIhot密钥。已知主机限制网络时由宿主在获准环境调用；不清楚时只做一次diagnose-aihot，按 [AIhot诊断](references/aihot-troubleshooting.md) 区分本机连接拒绝与HTTP服务故障，不盲目重试或伪造UA。保存完整响应、attribution、缓存原时间及原文时间，不把最近资讯冒充热榜。真实失败再转宿主搜索并标注平台。将五个有证据的候选保存topic-candidates.json，经intake.py candidates校验再展示；不足五个继续搜，不编造热度或来源。用户选择后apply写前答案，将角度、读者收益、实际信号、重复性理由写topic.json。同题需有新增变化。候选需有明确对象、具体读者场景和可兑现收益；同一热词换标题不算不同角度。候选的材料不足就补搜或换有证据的角度，不先编数字、体验和结果。
2. **核验与广搜。** 读 [全网研究与深度检查](references/research-depth.md)，先列读者问题，research.py plan生成平台查询计划，再由宿主实际搜索；网页/GitHub与X、抖音等分别检索，按本题扩展B站、小红书、知乎和公众号原文。有登录就用授权浏览器站内检索，没有则公开索引并如实记录缺口；不得称已连通所有平台。保存research-log、原始阅读记录及cases，摘要/平台AI总结不能算原始案例。资讯型至少两条独立来源及一条原始来源；同厂商两页不算两家。干货型有官方用法及可追溯操作。写sources、claims；未实际操作不写亲测、虚构心得或效率数字。案例区分第三方自报、厂商演示、模拟数据与我们实测。自选题证据不足如实说明，换题须答复；委托搜索题可有限换题。
3. **写作与深度。** 先完成问答、读证据，再做outline，每节有不同的问题、材料、推进作用与预算。按intake所选文风执行：卡兹克读取已装khazix-writer的SKILL.md，缺失明确用本包editorial简版；蒸馏风格执行style_library.py prepare，完整读五份规则与最相关五篇样本，记录校准后写作，完稿再核对实际风格使用与原创性。文风只改变表达与组织，不复制身份、经历、原句或历史事实；遵循所选风格，不一律套卡兹克口语。按 [内容组织与案例论证](references/content-craft.md) 的八项内容决策，用任务推进功能、用细节解释差异；技术案例保留输入/结果/失败，人物与组织案例保留目标/约束/不同声音。事实、解释、预测与体验各有适合的依据，不将情绪体验硬凑成量化实验，也不借鉴样本排版。依 [写法](references/editorial.md) 写无H1的body，每条事实在内部claims记来源、locator和当前body_quote。报道改稿另按 [阅读终审与叙事](references/news-reader-review.md) 检查人物推进、概念台阶和重复纠偏；两道语言审稿通过后仍需通读，结构返工后重新绑定两道审稿。长文按主任务展开可核验案例、对照、机制或处境，不用通用建议补长度，不强制人物与观点稿都给操作步骤。写depth-review逐节绑定当前材料和读者所得，保留有作用的叙事与停顿；research.py check通过后继续，自动检查不能代替通读。正文无引用和生成来源图注。通读成稿后按[题材与读者所得](references/reader-value.md)建立reader-value.json并check；新onboard启用的run将其纳入audit及指纹，工坊正文改动须更新，结构通过不冒称读者测试通过。
   **写后自然表达审稿。** 按[Humanizer与文风保留](references/humanizer-review.md)完整读取本包blader/humanizer，先保留风格草稿，再实际标记、改写、复核正文；保持所选文风、真实信息、命令与链接。教程用简单直白的手把手语气，不靠反复铺垫、假反问、鸡汤和套话凑篇幅。第一道完成后按 [双重去AI味检查](references/dual-tone-review.md) 读取独立版 lieflat-less-ai-tone，以 Humanizer 实际输出做第二道白名单清理，保留目标文风、段落结构和限定条件。审稿记录只留内部，更新改动段落的claims等映射；新run缺少任一道当前审稿不能通过audit。

4. **按内容配图。** 读 [配图与导出](references/visuals-layout.md)、[生图能力与配置分支](references/image-capability.md) 和 [真实局部截图](references/real-screenshots.md)。先通读正文，在images-plan记录每个关键段需要证据截图、概念图还是无需图片及原因；再确定实际图数。真实截图应有功能说明、数据与限定条件、案例产出或操作结果；仅有Logo、名称、发布日期或页面标题不能计为有效证据图。概念图解释抽象关系、分工、步骤或失败路径，不能重画截图里的事实或用文字卡片重复正文。不按固定1张截图、1—2张生图凑数。每张正文图记录它回答的问题、读者所得、选择该媒介的原因及删除后损失，重复或无增益就删。截图保留原像素并紧邻相关段落，不伪造界面。截图范围以[场景截图规则](references/screenshot-strategy.md)为唯一当前决策：教程完整一屏框操作区；整帖任务保留完整中文帖子；图表保留条件。当前用户指示优先，历史一屏/局部记录不覆盖新任务。按real-screenshots.md保存未标注原图并验证只有框线改变；其他用户可选择局部裁切。封面与需要的概念图按能力分支实际调用内置或用户已配置的生图工具；封面约2.35:1、中央1:1安全区、电影感杂志方向。图数不限上限，但逐图检查手机可读性和内容增益，避免连续证据堆叠打断阅读。页面不可访问时记录具体缺项，不用AI图冒充完成。登记并插入后运行`workflow.py check-images --run RUN`，通过再排版。
   **图片也要让普通读者迅速看懂。** 在证据同样可靠、用途相同的候选中，优先直观的原始案例、实际结果和操作画面。复杂图表有独特证据价值时可保留，须留下必要图例、坐标、单位和比较条件，并在紧邻正文用中文解释比较对象、关键结果及适用边界。按390px阅读宽度查看图片与相邻文字，检查一次扫读能否理解重点；英文密集、小字难辨或需要长时间解码时，换更直观原图或拆成单一问题。逐图在visual-review.checks.reader_comprehension记录具体判断；只验证“图片有用”或“文字能看见”不算完成。详见 [真实截图的理解验收](references/real-screenshots.md)。

5. **预排版与标题。** 读完整正文，recommend-layout绑定推荐与body hash；assemble不输出内部来源，layout通过zhouxing_adapter调用实际周行，合并本包已确认原创主题；缺失不静默换模板。读baokuan-title-generator及 [本包标题规则](references/titles.md)，后者覆盖短标题惯性与未经核验统计。先从已核验正文提取对象、受众/场景、可数条目、结果、取舍、代价和可交付资源；缺项换适合的角度，不凭空补承诺。内部生成12—18个候选、至少6个不同角度，展示3个推荐，默认偏好26—42可见字符，按内容允许例外，不凑长度。每项记录读者、点开理由、具体承诺、当前正文兑现段、评分及风险；不靠“来了/震撼”占满候选。titles绑定正文，research.py check --scope titles检查后选定标题与摘要，再assemble同步。用户指定固定标题优先记录例外。
6. **带动效预览与文章工坊。** 读 [预览、工坊与确认定稿](references/studio-motion.md)。通读本稿设计motion-plan，默认每篇有与内容对应的正文动效，用户可在预览关闭为静态版；不要把所有款式一起插入，也不让动效遮住必读内容。`workflow.py layout-previews --run RUN`继续生成十套真实周行主题与工坊资源，主题、正文图及本次字体一致。启动`studio.py serve --run RUN --port 0`，读取并打开实际URL，默认简洁文章预览，可进入工坊切换主题、调整字体/字号/组件/间距/动效并修改标题正文。无修改可直接发确认；有修改先“保存当前文章”，可恢复历史版本和未保存调整。另存排版模板不等于保存文章，模板只存设计。页面保存与测试点击均不授予传稿权限。
7. **确认保存版并验收。** 用户发确认后运行`studio.py status --run RUN`，读取最新保存版；有未保存修改不能上传旧版。`studio.py adopt --run RUN --revision N --decision <用户真实原话>`采用该版原始周行导出HTML；不要重跑默认layout覆盖工坊设计。纯排版改动保留正文，标题或正文改动先按保存稿更新证据、正文、标题及图片规划，必要的事实核验由Agent完成，不让用户重调排版或机械地再次确认。查看手机预览，执行真实富文本粘贴或编辑器HTML导入，保存roundtrip；fingerprint后记录review，包括动效用途、位置、实际播放、静态可读与密度的motion_design检查，再audit。旧run已有有效选择仍按原路径续作；新的工坊采用版由版本与HTML哈希校验，不用旧画廊覆盖其自定义样式。已有本次确认与入草稿指令就直接继续，不再另问是否上传。
8. **自动入草稿。** 读 [公众号连接与快速传稿](references/publishing.md)。首次登录目标公众号，读取或请用户提供名称与原始ID，记录其选排版后入草稿指令，bind-account写到工作目录.wechat-ai/account.json。之后复用账号配置，每次核对实际登录账号一致，不重复索要ID；登录过期需要用户扫码。无AppSecret也能走浏览器。先读[两条快速通道与动效门槛](references/fast-publishing.md)。prepare校验当前质量、排版选择、无待改项及目标账号，再用fast_publish.py plan判定官方API或browser_dom；不能为了走API删CSS或取消动效。API具备本地凭证、账号绑定、接口权限和长度条件时直接传稿；否则使用单独扫码后复用登录的Playwright目标页操作，不默认抢桌面焦点。新通道首次连接/标定尚未完成时具体说明缺项，不冒称自动入稿已经实测。正文与动效中实际使用的原图按SHA去重上传后transfer映射图片URL，并对已验证的四款单次动效生成绑定批准稿的无id依赖兼容版；原工坊版本、正文和内联CSS保持完整。真实富文本粘贴、封面裁切、保存、重新打开并verify；带动效稿另检查结构、引用与实际播放，丢失记需复核并修复，不静默去掉动效。只入草稿，发表由用户自行完成。已存同篇沿用draft_id，避免重复草稿。
